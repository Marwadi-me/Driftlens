The Real-World Dilemma

Code Moves Fast — Documentation Silently Becomes Wrong

Every day, pull requests introduce code changes that silently invalidate prose, tables, and API tutorials.

⚠️ Flag Renames & Obsolete Guides

A CLI flag is renamed (--timeout → --deadline), but user guides and tutorials continue explaining the obsolete flag name.

Code: parser.add_argument("--deadline", type=int, default=60) Doc: Use --timeout to terminate slow jobs.

⚠️ Altered Defaults & Stale Tables

A socket timeout changes from 30s to 60s in source code, but configuration tables in Markdown continue displaying 30s.

Code: export const DEFAULT_TIMEOUT = 60; Doc: | Setting | Default | => | DEFAULT_TIMEOUT | 30 |

⚠️ Modified Signatures & Broken Tutorials

Function signatures change (registerUser(email, password, tenantId)), yet public API tutorials describe the legacy parameters.

Code: function registerUser(email, password, tenantId) Doc: Call registerUser(email, password) to sign up.

⚠️ Deleted Features & Zombie Docs

An endpoint (/api/v1/legacy-export) is deleted from code, but remains documented as active in API docs.

Code: Route deleted in PR diff Doc: Use /api/v1/legacy-export to download reports in CSV.

System Philosophy

The DriftLens Solution: Hybrid Intelligence

Never send an entire repository blindly to an LLM. Combine deterministic AST parsing with bounded semantic AI.

1. Deterministic Grounding

AST/diff parser locates changed code hunks and tags every entity with exact file paths and line ranges. The AI never invents line numbers.

2. Sentence-Level Granularity

Documentation is chunked into individual sentence units and table rows with exact line ranges and section hierarchies (## Configuration).

3. Multi-Signal Filtering

Candidate matcher pairs changed entities with sentences using 4 distinct signals (exact names, old values, section keywords, file stems).

4. Bounded AI Reasoning

Qwen 2.5 7B evaluates only the tightly bounded pair: 'Does this code change contradict this sentence?' Strict JSON schema enforcement.

5. Same-PR Shield

Detects if the developer already updated the documentation in the same PR. If so, drift is suppressed, achieving zero false alarms.

6. 1-Click Auto-Remediation

Generates exact replacement suggestions, ready for 1-click in-browser patching or downloadable unified git .patch files.

Architecture Pipeline

End-to-End 6-Stage Analysis Workflow

How a Pull Request diff flows from raw Git commits into precise, verified documentation drift findings.

Stage 1: Git Diff Extraction

Runs git diff -U3 base...head or calls GitHub REST API. Classifies files into source, docs, tests, configs. Shallow clone resilient.

Stage 2: Entity Extraction

Statically extracts changed CLI flags (--timeout -> --deadline), constants, defaults, and API function signatures from diff hunks.

Stage 3: Documentation Chunking

Indexes all Markdown files in repo. Chunks text into sentence-level units with line offsets, sections, and table rows.

Stage 4: Multi-Signal Matching

Scores candidate pairs: Exact Identifier (+45%), Old Value Mention (+30%), Section Relevance (+15%), File Correlation (+15%).

Stage 5: Same-PR Suppression

Edge-case shield: If documentation was updated within the same PR hunk, drift is suppressed to prevent false alarms.

Stage 6: Qwen 2.5 7B Verification

Open-weight model evaluates semantic contradiction. Computes calibrated composite confidence and produces suggested fix.

Deterministic Matching

Multi-Signal Candidate Matching & Subword Lemmatization

Eliminating brute-force LLM evaluation by ranking top relevant sentences deterministically.

🎯 4-Signal Candidate Scoring Model

  • Signal A: Exact Identifier Match (+45%): Matches exact flag or constant name (e.g., --timeout, DEFAULT_TIMEOUT) in documentation text.
  • Signal B: Old Value Mention (+30%): Detects mentions of the previous implementation value (e.g., '30 seconds', '/api/v1/export') using boundary-aware regex.
  • Signal C: Section Context (+15%): Awards score if sentence appears under relevant headings like 'Configuration', 'CLI Options', 'API Reference'.
  • Signal D: File Path Correlation (+15%): Matches source file base name (src/config.js) to doc file base name (docs/config.md) or primary README.

🧩 Subword Tokenization & Root Lemmatization

Code identifiers rarely match prose word-for-word. DriftLens bridges this gap:

1. Identifier Splitting: DEFAULT_TIMEOUT -> ['default', 'timeout'] 2. Compound Word Decomposition: 'timeout' -> ['time', 'out'] 'endpoint' -> ['end', 'point'] 3. Suffix Stripping & Lemmatization: 'timing out', 'timed' -> root 'time' 4. O(1) Hash Set Lookups: Pre-computes _wordsSet and _stemsSet for O(1) matching!
Mathematical Calibration

Confidence Calibration Formula & Worked Example

A weighted composite formula balancing deterministic AST facts, candidate overlap, and LLM reasoning.

📐 The Composite Confidence Formula

Confidence = 0.35 × S_det + 0.25 × S_cand + 0.40 × S_llm

Worked Numerical Calculation (Renamed Flag Example):

  • S_det = 1.0: Hard AST shift: CLI flag renamed from '--timeout' to '--deadline'.
  • S_cand = 0.90: Candidate chunk explicitly matches old flag '--timeout' in 'CLI Options'.
  • S_llm = 0.97: Qwen 2.5 7B semantic reasoning confirms direct factual contradiction.
  • Calculation: 0.35(1.0) + 0.25(0.90) + 0.40(0.97) = 0.35 + 0.225 + 0.388 = 0.963 (96%)

🛡️ Strict 0.60 Confidence Threshold: Scores below 60% are discarded as noise.

🚦 Actionable Severity Tiers

  • 🔴 HIGH SEVERITY (Blocks CI): Direct factual contradiction: renamed flag, altered default, or deleted route. Exits with code 1, blocking PR merge.
  • 🟡 MEDIUM SEVERITY (Warning): Indirect semantic shift or parameter nuance. Flags PR with non-blocking warning annotation.
  • ⚪ LOW SEVERITY (Info): Minor stylistic or contextual documentation suggestions.
  • 🛡️ Zero False Alarm Shield: If the developer updated the documentation sentence in the same PR, DriftLens detects it and suppresses the finding.

Precision Engineering

False-Positive Control & The Same-PR Shield

Distinguishing between changes that need documentation updates vs those that are already handled.

🛡️ The Same-PR Update Shield

Scenario: A conscientious developer bumps DEFAULT_TIMEOUT = 60 and updates README.md to '60 seconds' in the same commit.

  • Hunk-Aware Proximity: DriftLens checks whether documentation changes in the PR overlap with the affected sentence lines.
  • New Value Verification: If the added lines in the doc hunk already contain the new value ('60') or renamed flag ('--deadline'), drift is suppressed.
  • Sentence Deletion Verification: If the obsolete statement was removed in the documentation diff, DriftLens acknowledges the fix.
  • The Result: Zero duplicate warnings when developers do their job correctly!

⚡ Non-Functional Code Change Filtering

  • Comments Are Not Entities: Code comments like '// TODO: change --timeout' are ignored so comments never trigger false drift.
  • Whitespace & Formatting Immunity: Internal code refactorings that preserve entity values (indentation, code cleanups) produce 0 findings.
  • Test File Isolation: Changes inside tests/, *.spec.js, or __tests__/ are automatically categorized as 'tests' and ignored for public documentation drift.
  • Strict Value Equality Check: If removed.value === added.value, the entity is recognized as unchanged and skipped immediately.
Complex Parsing

Parsing Structured Markdown Tables & API Signatures

Moving beyond plain paragraph text: How DriftLens parses tabular data and function signatures.

📊 Markdown Table Row Parser

Markdown tables present a major challenge for standard linters because values are split across column pipes (|):

  • Header & Delimiter Detection: Parses | Setting | Default | Description | and skips delimiter rows (|---|---|).
  • Row Data Objectification: Transforms each row into key-value pairs: { Setting: 'TIMEOUT_SECONDS', Default: '30' }
  • Precise Line Number Attribution: Tags the exact row line number in the source file, allowing 1-click in-table replacement.

🧩 Function Parameter Signature AST

Detecting when a function signature changes parameters without renaming the function:

  • Regex AST Pattern: function fnName(params) | def fnName(params) | const fnName = (params) =>
  • Parameter Signature Capture: Stores value as 'registerUser(email, password)' vs 'registerUser(email, password, tenantId)'
  • Signature Comparison: Detects parameter addition or deletion even when the function name itself remains unchanged.
  • Accurate Remediation: Replaces the obsolete parameter list in prose tutorials while preserving contextual wording.
